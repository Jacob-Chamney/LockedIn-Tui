# Licensing notes for the Flutter migration

This is engineering guidance, not legal advice. Have counsel confirm before a
release.

## Toolchain

- **Flutter** — BSD-3-Clause.
- **Dart** — BSD-3-Clause.
- **Flutter engine** — BSD-3-Clause plus third-party notices; `flutter build`
  produces the notices with the artifact.
- **Material/Cupertino widget libraries** — BSD-3-Clause.
- **Bun** — MIT.
- **Current app source** — AGPL-3.0-only (public repository).
- **Qt** — not used by this frontend. No Qt LGPL/GPL module or source-offer
  obligations are introduced by the desktop app.

## Audit — what the Linux artifact actually ships

Checked on 2026-11-16 against `dist/lockedin-desktop-linux-x64.tar.gz` (28
entries, 62 229 628 bytes) built by `scripts/desktop-package.sh`.

The artifact contains exactly two licence-bearing files:

| Entry | Covers |
|---|---|
| `LICENSE` | the application — AGPL-3.0-only (`scripts/desktop-package.sh` copies the repository `LICENSE` to the archive root) |
| `data/flutter_assets/NOTICES.Z` | Flutter framework, Dart SDK, the engine's bundled third-party libraries and every Dart package compiled into `libapp.so` — 103 231 bytes, 115 named components, generated by `flutter build linux --release` |

`NOTICES.Z` is generated, not hand-written: it is the authoritative notice set
for the Flutter half, and it names the Dart packages that ship —
`material_ui` 1.11.0 (BSD-3-Clause), `cupertino_ui` 1.1.6 (BSD-3-Clause),
`cupertino_icons` 1.0.9 (MIT), `file_selector` 1.1.0 and its platform packages
(BSD-3-Clause), `intl` 0.20.3, `http` 1.6.0, `vector_math` 2.4.3,
`material_color_utilities` 0.13.0 (Apache-2.0) and the rest of
`desktop/pubspec.lock` — alongside the engine libraries (Skia, ICU, BoringSSL,
zlib, HarfBuzz, FreeType, libpng, libjpeg-turbo, libwebp, libjxl, Vulkan
components …).

The other half is `lockedin-core`, a `bun build --compile` binary. It embeds the
Bun runtime (MIT) and 24 npm packages; `bun build --metafile` lists the module
graph, and the licence identifiers are MIT, Apache-2.0, BSD-3-Clause and ISC:
`ai` 7.0.159 and the `@ai-sdk/*` family (Apache-2.0), `@modelcontextprotocol/sdk`
1.32.2, `zod` 4.6.7, `ajv` 8.20.0, `fflate` 0.8.3, `cross-spawn` 7.0.6,
`eventsource-parser`, `fast-deep-equal`, `json-schema-traverse`, `path-key`,
`shebang-command`, `shebang-regex` (MIT), `smol-toml` 1.9.1, `fast-uri` 3.1.9
(BSD-3-Clause), `which` 2.0.2, `isexe` 2.0.0, `zod-to-json-schema` 3.25.2 (ISC).
The canonical inventory with versions and licence texts is the generated
`THIRD-PARTY-NOTICES.md`.

Two findings from the audit:

- **The native keychain addon is not redistributed.** The bundle carries no
  `.node` file, so a packaged core falls back to the `secret-tool` command shim
  (`createSystemSecretStore`). `@napi-rs/keyring` (MIT) therefore needs no
  notice in the artifact, and the keychain stays keychain-only.
- **The Bun half has no notice in the artifact.** `NOTICES.Z` is generated by
  Flutter and covers only Flutter/Dart/engine; it says nothing about Bun or the
  npm packages compiled into `lockedin-core`. The repository already generates
  the sidecar's notice set — `THIRD-PARTY-NOTICES.md`, written by
  `bun run scripts/licenses.ts` from `bun.lock` and verified by
  `tests/unit/licenses.test.ts`, embedding Bun's own notice and
  `licenses/BUN-LICENSE.md` — but `scripts/desktop-package.sh` copies only
  `LICENSE` into the bundle, so that file does not ship. Until it does, a
  release is missing Bun's MIT notice, the LGPL-2 JavaScriptCore/WebKit notice
  that Bun embeds, and the Apache-2.0/MIT/BSD/ISC notices of the bundled
  packages. This is the one blocking gap, tracked in `desktop/tasks/T-007-qa.md`;
  `NOTICE` inventories the artifact and points at the generated files.

No dependency ships a browser or a second rendering engine, and none is
GPL/AGPL; Flutter/Dart (BSD-3-Clause) and Bun (MIT) are both compatible with the
app's AGPL-3.0-only licence.

## App licence decision (pending)

The current public source is AGPL-3.0-only. Flutter/BSD is compatible with it.
If the product later moves to MIT:

1. The AGPL→MIT change needs permission from every copyright holder. This
   repository uses a DCO, not a CLA, so audit contributors before relicensing.
2. Keep the existing notices and attribution.
3. The Bun core and Flutter shell can both be MIT; third-party packages keep
   their own terms.

Do not change the repository licence as part of a feature packet. It is a
product/legal decision with its own review.

## Dependency policy

- Prefer **MIT, BSD, Apache-2.0** packages.
- Avoid **GPL/AGPL** UI packages unless the whole distribution is compatible.
- Avoid packages that bundle a browser or a second rendering engine.
- Every new package needs its licence recorded in the PR and, if it ships in
  the binary, added to the notices.
- No package may read the workspace, keychain or provider keys directly.

## Release checklist

- `flutter build linux/windows --release` includes the Flutter/Dart notices —
  **done**: `data/flutter_assets/NOTICES.Z` is in the tarball and verified by
  `scripts/desktop-package.sh`'s `REQUIRED` list.
- `LICENSES/` and `NOTICE` list third-party packages and their versions —
  **met by generated files, not `LICENSES/`**: `NOTICES.Z` is regenerated by
  every `flutter build`, `THIRD-PARTY-NOTICES.md` is committed and checked
  against `bun.lock`, and `NOTICE` (new, 2026-11-16) inventories the artifact and
  points at both. Packaging is still partial: `scripts/desktop-package.sh`
  stages only `LICENSE`, so `THIRD-PARTY-NOTICES.md` and `NOTICE` do not reach
  the tarball. Add them to the staged bundle and to `REQUIRED` before a public
  release.
- The bundled core binary reports its version; the shell and core ship together.
- No secrets, tokens or workspace paths in logs, fixtures or screenshots.
- If the app licence changes, update `LICENSE`, `README`, `CONTRIBUTING` and the
  public repository metadata in the same change.
